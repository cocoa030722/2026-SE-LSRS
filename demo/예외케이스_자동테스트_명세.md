   ```powershell
   .\gradlew.bat test --tests "com.se.lsrs.policy.service.*" --tests "com.se.lsrs.reservation.service.*" --tests "com.se.lsrs.user.service.*"
   ```
2. Seed를 실행한 직후 상태에서 시작한다 (데모 문서 4장 3단계).
3. Git Bash 창을 열고 아래 **공통 준비 명령**을 붙여 넣는다. 토큰은 1시간이면 만료되므로 **데모 직전에 다시 실행한다.**

### 공통 준비 명령 (Git Bash, 창마다 한 번)

```bash
set +H
B=http://localhost:8080/api; J='-H Content-Type:application/json'
W='-w \n[HTTP %{http_code}]\n'
login(){ curl -s $J -X POST $B/auth/login -d "{\"loginId\":\"$1\",\"password\":\"Passw0rd!\"}" | sed -E 's/.*"accessToken":"([^"]+)".*/\1/'; }
A=$(login 20260001); ADM=$(login admin)
TMR=$(date -d tomorrow +%F); TODAY=$(date +%F)
echo "A=${A:0:20}...  ADM=${ADM:0:20}...  TMR=$TMR"
```
- `set +H`: 비밀번호 `Passw0rd!`의 `!` 때문에 필요하다 (없으면 `event not found` 오류).
- `W`: 응답 뒤에 `[HTTP 409]`처럼 상태 코드를 한 줄 더 찍는다.
- 마지막 줄에서 `A=`, `ADM=` 뒤가 `eyJ`로 시작하면 로그인에 성공한 것이다.

### 자동 테스트: `ReservationConcurrencyTest` (2건, 실제 MySQL)

**공통 구조**
- **데이터:** `fixture-concurrency.sql`로 학생 20명(user 1~20), 좌석 20석을 넣는다. 현재 시각은 2026-12-01 10:00으로 고정하고, 예약 시간대는 같은 날 13~15시다.
- **동시 출발:** 스레드 20개가 모두 `ready` 래치에서 준비를 마칠 때까지 기다리고, `go` 래치 하나를 열어 **같은 순간에** `reservationService.reserve()`를 호출한다.
- **실제 커밋:** 요청마다 자기 트랜잭션으로 실제 커밋한다(테스트 롤백을 쓰지 않음). 그래야 DB 잠금 경쟁이 실제로 일어난다. 앞뒤 데이터는 `cleanup.sql`로 지운다.
- **결과 집계:** 각 요청 결과를 성공(`OK`) 또는 오류 코드로 모아 건수를 센다.

| 테스트 메서드 | 상황 | 검증 내용 |
|---|---|---|
| `학생_20명이_같은_좌석_같은_시간대를_동시에_예약하면_1건만_생성된다_AC4` (127행) | 학생 1~20이 **좌석 1번 하나**를 동시에 예약 | ① 결과가 정확히 `OK 1건 + SEAT_ALREADY_RESERVED 19건`이고 다른 결과(서버 오류 등)는 없다. ② DB에서 좌석 1번의 진행 중 예약을 직접 세면 **1건** |
| `한_학생이_같은_시간대에_좌석_20개를_동시에_예약하면_1건만_생성된다_FR_R_11` (135행) | 학생 1번이 **좌석 1~20번**을 동시에 예약 | ① `OK 1건 + DUPLICATE_RESERVATION 19건`. ② DB에서 학생 1번의 진행 중 예약 **1건** |

**두 테스트가 각각 증명하는 것**
- 첫 번째: **좌석 행 잠금**(`SELECT … FOR UPDATE`)으로 같은 좌석 요청이 줄을 서고, 뒤 요청은 앞 요청이 저장한 예약을 보고 거부된다 (US-06 AC4 "이중 배정 0건").
- 두 번째: 좌석이 서로 달라 좌석 잠금끼리는 부딪히지 않는다. 그래도 1건만 생기는 것은 **학생 행 잠금**이 동작한다는 뜻이다 (한 학생은 같은 시간대에 예약 1개).
- 공통: 거부된 19건은 DB에 남지 않는다 → 오류가 나면 롤백된다 (US-06 AC5).

🎤 (결과 창을 가리키며) "스레드 20개를 실제 MySQL에서 같은 순간에 출발시켰습니다. 같은 좌석은 20명 중 1명만, 한 학생이 좌석 20개를 동시에 눌러도 1건만 생깁니다. 건수는 서비스 판단이 아니라 DB를 직접 세서 확인합니다."

## E2. 경계값

### 라이브 시연 (약 30초)

| 순서 | 입력 | 보여야 할 것 |
|---|---|---|
| 1 | 학생A: 평상시 5시간 예약, 내일 13~18시 (화면은 최대 4시간까지만 고를 수 있으므로 API 요청) | 400 "평상시 최대 이용 시간은 4시간입니다." |


🎤 "경계값은 '경계 바로 안쪽은 통과, 바로 바깥은 거부'를 한 쌍으로 테스트했습니다. 화면에서는 바깥쪽 거부만 보여 드리고, 안쪽 통과는 테스트 결과로 보여 드리겠습니다."

## E3. 권한 오류·잘못된 입력

### 라이브 시연 (약 30초, Git Bash)

| 순서 | 입력 | 보여야 할 것 |
|---|---|---|
| 1 | 토큰 없이 내 예약 조회 | 401 `UNAUTHENTICATED` "로그인이 필요합니다." |
| 2 | 학생A 토큰으로 관리자 정책 API | 403 `ACCESS_DENIED` "접근 권한이 없습니다." (화면: 학생이 정책 관리 주소로 가면 권한 없음 화면) |
| 3 | 학생A 토큰으로 **학생B의 예약 1번** 취소 | 404 `RESERVATION_NOT_FOUND` "예약을 찾을 수 없습니다." |

```bash
# 1. 토큰 없이 내 예약 조회 → 401 "로그인이 필요합니다."
curl -s $W $B/reservations/me

# 2. 학생A 토큰으로 관리자 정책 API → 403 "접근 권한이 없습니다."
curl -s $W -H "Authorization: Bearer $A" $B/admin/policies

# 3. 학생A 토큰으로 학생B의 예약 1번 취소 → 404 "예약을 찾을 수 없습니다."
curl -s $W -H "Authorization: Bearer $A" $J -X PUT $B/reservations/1/cancel -d '{"reason":"OTHER"}'
```

🎤 "남의 예약에 403이 아니라 404를 주는 건 의도입니다. 403이면 '그 번호의 예약이 있다'는 사실이 새기 때문에, 조회 자체를 '내 예약 중에서' 하도록 만들어 남의 예약은 없는 것으로 취급합니다."

### 자동 테스트: `Us07Us08IntegrationTest` (실제 MySQL + MockMvc)

**구조:** `@SpringBootTest` + Testcontainers MySQL. `fixture-reservations.sql`로 학생 1·2, 좌석 2개, 예약 5건(10 체크인 완료, 11 예약중, 12 취소됨, 13 **학생2의** 예약중, 14 노쇼)을 넣는다. 요청은 MockMvc로 컨트롤러부터 DB까지 전 계층을 거친다. 테스트마다 트랜잭션을 롤백한다.

**질문 대비: 이 테스트의 한계**
이 통합 테스트는 로그인 사용자를 `@WithMockUser`로 대신 넣어서, **실제 JWT 토큰 검증 코드는 거치지 않습니다.** 실제 토큰 경로는 위 라이브 시연(curl)이 보여 줍니다. "토큰을 위조하면?"이라는 질문이 나오면 Q&A 노트 Q39로 답합니다.
