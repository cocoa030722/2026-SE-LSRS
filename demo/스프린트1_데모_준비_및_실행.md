### 이번에 적용한 변경 (미커밋, 작업 트리)
**백엔드**
- `AuthService`: 비밀번호 규칙 검증과 부족한 항목 안내(`보완할 항목: 영문, 특수문자`), 로그인 시 **비밀번호를 먼저 확인**한 뒤 PENDING이면 `EMAIL_NOT_VERIFIED`(401, "이메일 인증이 필요합니다…")
- `JwtProvider`: Access 토큰 만료 30분 → **1시간**
- `UserService.withdraw`: 학생 행을 잠근 뒤(예약 생성과 같은 잠금) 진행 중 예약(RESERVED·CHECKED_IN) 또는 이용 제한이면 `WITHDRAW_NOT_ALLOWED`(409, "진행 중인 예약 또는 패널티가 존재하여 탈퇴할 수 없습니다.")
- `ErrorCode`, `ReservationRepository.existsByUserUserIdAndStatusIn` 추가
- 테스트 10건 추가: `AuthServiceTest`(7), `UserServiceTest`(3)

**프론트엔드**
- `tokenStorage`(localStorage, JWT 디코딩), `client.js`(Bearer 첨부, 401→로그인 화면, `ACCESS_DENIED` 403→권한 없음 화면), `AuthProvider`, `RequireAuth`, `RootRedirect`(역할별 첫 화면: 학생 좌석 예약, 관리자 정책 관리)
- `LoginPage`·`SignupPage`·`VerifyEmailPage`·`AccountPage`(탈퇴)·`MainLayout`(로그아웃)
- 백엔드에 맞춘 점: 이메일 인증은 `GET /api/auth/verify-email?token=`, 로그인·가입·인증 요청에는 토큰을 붙이지 않음(서버에서 무효가 된 토큰이 남아 있어도 로그인 가능), 이용 제한(`USER_RESTRICTED`) 같은 업무 403은 화면에서 안내하고 권한 없음 화면으로 보내지 않음

## 3. 테스트 계정 (`demo/seed-demo.sql`)

모든 계정 비밀번호: **`Passw0rd!`**

| 로그인 ID | 역할·상태 | 데모 용도 |
|---|---|---|
| `admin` | ADMIN | US-07 시험 기간·정책 설정, US-02 AC4 |
| `20260001` | 학생A, 노쇼 1회 | **메인 시연 계정.** 이력: 체크인 완료(B-01) / 취소됨(B-02, 일정 변경) / 노쇼(B-03) |
| `20260002` | 학생B | 다른 학생. 내일 10~12시 A-02 예약(→ '예약됨'), 현재 시간대 A-03 체크인(→ '사용 중'). 실시간 반영 확인용 두 번째 창 |
| `20260003` | 학생C, 이용 제한(Seed 실행 + 3일) | US-06 AC3 예약 거부, US-04 AC2 탈퇴 거부 대상. 내일 14~16시 D-01 예약 보유 |
| `20260004` | 학생D, 예약 없음 | US-04 AC1·3 탈퇴 → 재로그인 거부 |
| `20260005` | 학생E, PENDING | US-02 AC2 미인증 로그인 |

- 좌석: 4행 × 5열 `A-01`~`D-05` (seatId 1~20, A-01=1, A-02=2, … B-04=9, … D-01=16)
- Seed 직후 예약 id: 1=학생B 내일 A-02, 2=학생B 현재 A-03(체크인), 3=학생A 체크인 완료, 4=학생A 취소, 5=학생A 노쇼, 6=학생C 내일 D-01. 데모 중 새 예약은 7번부터 생긴다.
- 날짜는 실행 시각 기준(`CURDATE()`·`NOW()`)으로 만든다. **A-03 '사용 중'은 실행한 시각의 정시부터 2시간만 보이므로 데모 직전에 실행한다.**
- 기존 users·seat·reservation·exam_period·verification_tokens를 **모두 지우고** 정책 파라미터를 기본값으로 되돌린다. 리허설 뒤 다시 실행하면 같은 상태로 돌아온다.

## 4. 환경 준비 절차 (Windows PowerShell)

### 사전 조건
- R1(커밋·PR 병합) 후 `git switch main; git pull`
- Docker Desktop 실행 중일 것 (`docker info`가 응답해야 함). `bootRun`이 `compose.yaml`의 MySQL을 자동으로 띄운다.
- JDK는 Gradle toolchain(21)이 자동으로 받는다. 처음 실행할 때 인터넷이 필요하다.
- Node.js는 기술스택 문서 기준 26.13.1을 권장한다 (22.x에서도 빌드는 확인함).
- **데모 시작 30분 전에 1~7단계를 끝낸다.**

### 1단계: 빌드
```powershell
.\gradlew.bat clean compileJava
```

### 2단계: 백엔드 실행 (이 창은 데모 내내 열어 둔다)
```powershell
# JWT_SECRET 설정은 필요 없다 (application.properties에 데모용 기본 키가 있음)
.\gradlew.bat bootRun
```
- `Started LsrsApplication` 로그가 나오면 준비 완료 (약 30초, 포트 8080).
- MySQL 컨테이너 이름은 **`2026-se-lsrs-mysql-1`** 이다 (`docker ps`로 확인). 호스트 포트는 매번 무작위다.
- US-01 인증 토큰이 이 창에 출력된다. 글자 크기를 키워 둔다.

### 3단계: Seed (데모 직전에 다시 실행)
```powershell
Get-Content -Raw -Encoding UTF8 demo\seed-demo.sql | docker exec -i 2026-se-lsrs-mysql-1 mysql -ulsrs -plsrs lsrs
docker exec 2026-se-lsrs-mysql-1 mysql -ulsrs -plsrs lsrs -e "select count(*) from seat; select login_id,status,role from users;"
```
좌석 20개, 계정 6개가 나오면 성공이다. Git Bash에서는 `docker exec -i 2026-se-lsrs-mysql-1 mysql -ulsrs -plsrs lsrs < demo/seed-demo.sql`로 실행한다.

### 4단계: 프론트엔드
```powershell
cd frontend
npm install      # node_modules가 없을 때만
npm run dev      # http://localhost:5173  (/api → 8080 프록시)
```

### 5단계: 테스트 결과 창 미리 띄우기 (6장 예외 케이스용)
IntelliJ에서 다음 테스트를 실행한 뒤, 결과 창을 열어 둔다.
- `ReservationConcurrencyTest`, `Us07Us08IntegrationTest`: 둘을 합쳐 약 1분, Docker 필요
- `PolicyServiceTest`, `ReservationServiceTest`: 약 13초, Docker 불필요. 데모 중 그 자리에서 실행해도 된다

명령줄로 실행할 때:
```powershell

.\gradlew.bat test --tests "com.se.lsrs.ReservationConcurrencyTest" --tests "com.se.lsrs.Us07Us08IntegrationTest"
.\gradlew.bat test --tests "com.se.lsrs.policy.service.*" --tests "com.se.lsrs.reservation.service.*"
```

### 6단계: 자동 점검 (선택, 리허설 때 권장)
시연 순서 전체를 Edge로 화면에서 그대로 실행해 AC를 점검한다 (2026-11-16 기준 37개 점검 모두 통과). **데이터를 바꾸므로 실행 후 3단계 Seed를 다시 실행한다.**
```powershell
cd demo\rehearsal
npm install                       # 처음 한 번 (playwright-core)
node demo.mjs <bootRun 로그 파일>  # 이메일 인증 토큰을 이 로그에서 읽는다
```
- `bootRun` 출력을 파일로 남기려면 2단계를 `.\gradlew.bat bootRun *> boot.log`로 실행한다 (콘솔에는 보이지 않으므로 평소에는 쓰지 않는다).
- Edge 경로가 다르면 `$env:EDGE_PATH`를 지정한다. 마지막 줄 `RESULT pass=37 fail=0`이면 정상이다.

### 7단계: 첫 화면 점검
- [ ] `http://localhost:5173` → 로그인 화면
- [ ] `20260001` 로그인 → 좌석 화면에 "평상시 정책 · 최대 4시간"과 20석이 보인다

- [ ] 시크릿 창 2개에서 `20260002`, `admin` 로그인
- [ ] IntelliJ: 7장 코드 탭, 5단계 테스트 결과 창
- [ ] **3단계 Seed를 다시 실행해 초기화** (리허설 흔적 제거)

### 데모 후
`bootRun` 창에서 Ctrl+C. 컨테이너까지 지우려면 `docker compose down`.
